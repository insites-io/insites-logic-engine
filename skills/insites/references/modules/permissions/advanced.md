# Permissions — Advanced

Hooks, partials other modules render, and what this module borrows. Paths are under `pos/modules/insites_permissions/` in module-v6-permissions v6.0.2 unless stated (read 9 October 2026).

## Hook

`public/views/partials/lib/hooks/hook_module_info.liquid` answers the platform's module-discovery hook. It runs CRM's `hook/get_implementations` GraphQL to find its own partial's `updated_at`, then returns:

```json
{ "name": "Insites Permissions", "machine_name": "insites_permissions", "type": "module", "version": "6.0.0", "updated_at": "<partial updated_at>" }
```

Consume it; do not override it. The version lags the tag (see [`gotchas.md`](gotchas.md) item 2).

## Partials other modules render

CRM includes these when `context.modules.insites_permissions` is set:

| Partial | Rendered by (CRM v6.1.2) | Content |
|---|---|---|
| `private/views/partials/insites_menu/insites_permissions_side_menu.liquid` | `insites_admin/insites_side_menu_controller.liquid` | `<ins-sidebar-item>` "Permissions" with one child, Profiles (`#/permissions/profiles`) |
| `private/views/partials/insites_admin/insites_permissions_dependencies.liquid` | `insites_admin/insites_module_dependencies.liquid` | preload and stylesheet links for the SPA's CSS and JS |
| `private/views/partials/insites_admin/insites_permissions_index_dependencies.liquid` | `insites_admin/insites_index_module_dependencies.liquid` | `<div id="insites-permission-manager">` plus the `app.*.js` script, mounted under the `/permissions` hash prefix |

The two `insites_admin` partials are generated by `vue/scripts/write-dependency-partials.mjs` on build and carry a "do not edit" header; the hashed asset names change on every build.

## Public partials

`public/views/partials/api/` holds three "insert your liquid code below" policy partials: `ins_assign_contact_permission_api_authorization_policy`, `ins_get_contact_permissions_api_authorization_policy`, `ins_get_groups_list_api_authorization_policy`. Each returns `true`. They are the module's only stated override points and nothing references them. `public/views/pages/api_401.html.liquid` is a public 401 page on slug `api/401` (see [`gotchas.md`](gotchas.md) item 8).

## What it borrows from CRM

Every reference below resolves in `module-v6-crm` at `pos/modules/insites_crm/`:

- `private/authorization_policies/insites_only_allowed_by_administrators.liquid`: the guard on all 12 pages.
- `private/views/layouts/json.html.liquid`: the layout on seven pages.
- `private/views/partials/functions/response_handler.liquid`: body, headers, status (default 400).
- `private/views/partials/functions/generate_sort.liquid`: sort builder. The module ships an identical, uncalled copy under its own `functions/`.
- `private/views/partials/functions/event_stream/get_api_key.liquid`: reads instance configuration `event_stream_api_key`.
- `private/api_calls/event_stream/add_event.liquid` and `get_events.liquid`: the templates named `modules/insites_crm/add_event` and `get_events` in `private/graphql/event_stream/*.graphql`.
- `private/graphql/hook/get_implementations.graphql`: used by the hook.
- `private/user_profile_types/{administrator,crm_contact,token}.yml`: the protected list in `delete_profile` and `edit_profile`.

## Event-stream payload

The four functions in `private/views/partials/functions/profiles/event_stream/` build the same payload: `datetime`, an HTML `description` linking the administrator (`/admin/insites/#/crm/contacts/<id>`) and the profile (`/admin/insites/#/permissions/profiles/<id>`), `administrator_uuid` (`context.current_user.external_id`), `module_source: insites_permissions`, `module_feature: profiles`, `log: { profile_id, action, data }` (`edit_profile` adds `before`), `font_icon`, `font_icon_color` and `request_type: internal`. Actions: `add_profile`, `edit_profile`, `delete_profile`, `empty_profile`. `remove_contact` has its history call commented out.

## Where profiles land

The admin UI writes schemas under `modules/ins_profiles/` (`vue/src/views/Permissions/Profiles/sections/Details/Details.vue`), not `modules/ins_permission_manager/`. CRM's v2 contact controllers surface any profile not under `modules/insites_crm/`, so both prefixes pass; the `ins_permission_manager` name in CRM comments and in [`../crm/gotchas.md`](../crm/gotchas.md) is the v5 module name, also visible in the CMS migration `20220428012358_system_api_endpoints_v5.0.0.liquid`.
