# Assets: Configuration

What an administrator sets up in IIA, and what deploying the module seeds. Paths are relative to `pos/modules/insites_assets/` in module-v6-assets v6.1.0, read on 9 October 2026.

## IIA screens

The side menu partial `private/views/partials/insites_menu/insites_assets_side_menu.liquid` adds four entries; the routes come from `vue/src/router/*.js`.

| Screen | IIA path | What it does |
|---|---|---|
| All Assets | `<your-insites-instance>/admin/insites#/assets/all-assets` | Browse folders, upload, edit metadata, archive, restore, delete. Uploads run through `GET /insites/assets/credentials` then `POST /insites/assets/files`. |
| Event Stream | `<your-insites-instance>/admin/insites#/assets/event-stream` | The CRM event stream filtered to this module's events (`add_file`, `edit_file`, `archive_file`, `restore_file`, `delete_file`, `add_folder`, `delete_folder`). |
| Reports | `<your-insites-instance>/admin/insites#/assets/reports` | Storage and count buckets from `controllers/reports/get_asset_summary.liquid`; loading it also calls `reports/check-file-sizes`, which may enqueue the file-size reconcile job. |
| Configuration | `<your-insites-instance>/admin/insites#/assets/configuration` | Upload restrictions. |

## Upload restrictions

The Configuration screen (`vue/src/views/Configuration/sections/UploadRestrictions/UploadRestrictions.vue`) edits three fields: `mode` (`denylist` or `allowlist`), `extensions` (list), `max_file_size_mb` (blank means the 600 MB ceiling, `MAX_UPLOAD_FILE_SIZE_MB` in the same file).

**The record lives in the CRM module, not here.** The screen reads and writes `/insites/core/upload-restrictions` (`vue/src/services/UploadRestrictionsServices.js`), and the server-side checks call `modules/insites_crm/functions/validate_upload` and `modules/insites_crm/upload_restrictions/get_upload_restrictions`. The module's own test `private/lib/test/upload_restrictions/validate_upload_doors_test.liquid` assumes a seeded default denylist that contains `php`; the seeding itself is CRM's. An instance whose CRM does not serve that endpoint gets a Configuration screen that cannot load or save (the dependency in TW#26813287).

Three doors enforce the rules: `controllers/credentials/get_details.liquid` (before any credentials exist), `controllers/files/add.liquid` (admin register), and `controllers/_external/v2/assets/create.liquid` (API register). The last two check the extension only.

## What deploy seeds or migrates

- **Schema:** `private/schema/assets_upload.yml` creates table `modules/insites_assets/assets_upload` with `uuid` (string) and `asset` (upload). `controllers/files/add.liquid` writes one row per admin upload through `private/graphql/add_asset_upload.graphql`; nothing in the module deletes those rows.
- **Migration:** `private/migrations/20251110103359_move_all_invalid_assets.liquid` pages through assets whose `physical_file_path` starts with `/` and rewrites each to `modules/ins_assets/public/assets` + the old path.
- **Admin bundle partials:** `private/views/partials/insites_admin/insites_assets_dependencies.liquid` and `insites_assets_index_dependencies.liquid` are generated by `vue/scripts/write-dependency-partials.mjs`. The built bundle under `private/assets/insites_admin/app/` is gitignored (`SEED.md`); run the Vue build before `insites-cli deploy`.
- **No seeded records** and no settings table of the module's own.

## Out of scope

Install and version updates happen through the Insites console. Roles do not exist; access is the two CRM policies named in [`api.md`](api.md). The instance API key is managed as in [`../../api/authentication.md`](../../api/authentication.md).
