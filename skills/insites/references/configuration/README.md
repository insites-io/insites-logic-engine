# Configuration

## .insites File (Environment Endpoints)

Located at project root. JSON file generated by `insites-cli env add`. Defines environment credentials:

```json
{
  "dev": {
    "instance_uuid": "uuid",
    "token": "token",
    "email": "dev@example.com",
    "url": "https://your-instance.staging-insites.io",
    "key": "key"
  }
}
```

## app/config.yml (Feature Flags)

Application-level configuration. Flags are flat top-level keys:

```yaml
# app/config.yml
liquid_raise_mode: true
slug_exact_match: false
escape_output_instead_of_sanitize: false
redirect_trailing_slash: true
```

There is no `modules:` section: modules are installed through the Insites Console (see [Module Configuration](#module-configuration)).

Flags that changed behaviour in 2026, all set in `app/config.yml`:

| Flag | Default | What it does |
|---|---|---|
| `string_interpolation` | off on existing instances, on for new | `{{ }}` inside double-quoted strings renders. Breaking for templates that keep a literal `{{ }}` in double quotes. See [types](../liquid/types/api.md). |
| `liquid_raise_mode` | `true` | A filter that rejects its arguments stops the render with a 500 and a diagnostic. Leave it on: off, a failed filter returns `''` or `false` and silently picks a branch. |
| `websockets_require_subscribed_partial` | `true` | A WebSocket channel with no `channels/<name>/subscribed` partial rejects every subscription instead of admitting any same-origin subscriber. |
| `websockets_require_csrf_token` | on for new instances | Every `subscription.send` must carry the CSRF token; the token the socket was opened with now counts. |
| `auto_manage_public_only_modules` | `false` | A module with only `public/` files is treated like app files on deploy, so files removed from the deploy are deleted. Opt in with care: it is a cousin of `modules_that_allow_delete_on_deploy`, which deletes a module's migration-written views when a module is flagged. |

A property missing from `app/config.yml` is a logged warning, not an error (26 February
2026), and an unknown property, a flag the target environment does not know yet for
example, no longer fails the deploy (20 April 2026).

`slug_exact_match` is also set in `app/config.yml`. When it is `true`, a page answers only its own slug, and a page that reads an id from a deeper path stops working. Both instances measured on September 26, 2026 behaved as if it were off. See [A Static Slug Also Answers Deeper Paths](../routing/gotchas.md#a-static-slug-also-answers-deeper-paths).

## Constants (Runtime Configuration)

For secrets and environment-specific values. See `references/constants/`.

```bash
insites-cli constants set --name KEY --value "value" dev
```

## Environment Detection

```liquid
{% if context.environment == 'staging' %}
  {% comment %} Staging-only behavior {% endcomment %}
{% endif %}

{% if context.environment == 'production' %}
  {% comment %} Production-only behavior {% endcomment %}
{% endif %}
```

## Module Configuration

Modules are configured via installation and constants:

```bash
# Pull module from instance
insites-cli modules pull payments dev

# Configure module via constants
insites-cli constants set --name stripe_sk_key --value "sk_..." dev
```

Modules are installed and updated through the Insites Console. The CLI cannot install one, but it can remove one: `insites-cli modules remove <env> <name>` removes the module's configuration **and its data** from the instance, so treat it as a destructive command and take a backup first. `insites-cli modules list <env>` shows what is installed.
