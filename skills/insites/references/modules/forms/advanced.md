# Forms — Advanced

Hooks, partials other code renders, and what this module needs from other modules. Paths are relative to the module root `modules/insites_forms/` unless they start with `modules/`.

## Hook

`modules/insites_forms/lib/hooks/hook_module_info` is the only partial under `public/`. It answers CRM's `hook/get_implementations` registry with `name`, `machine_name`, `type`, `version` (`6.0.3`) and `updated_at`. Use it for "is Forms installed"; [`../crm/advanced.md`](../crm/advanced.md) explains why the version can lag on other modules.

## Partials the embed code depends on

Private by location, but every published form includes them, so they are the module's contract:

| Partial | Used for |
|---|---|
| `modules/insites_forms/form_code` | Stylesheet and five scripts from `components.insites.io/forms/` (uploader, field value, validations, conditions, processor) |
| `modules/insites_forms/form_localisation` | `{ date_format, time_format, no_meridiem }` from `modules/insites_crm/localisation`; defaults `YYYY-MM-DD`, `h:mm A` |
| `modules/insites_forms/form_properties` | Merges `form.fields.properties` with `form.metadata.properties` for the processor |
| `modules/insites_forms/form_redirect` | `{ "redirect_to" }` for the named form, default `/` |
| `modules/insites_forms/form_code/label`, `placeholder`, `tooltip`, `validation/*` | Per-field attribute helpers; `validation/length` writes an empty `maxlength` (the real line is commented out) |
| `modules/insites_forms/form_scripts` | Older bundle paths, kept "for OLD version of forms" |

## Data-source option partials

`private/views/partials/data_source/` renders `<ins-input-select-option>` lists for reference fields: `crm/companies`, `crm/users`, `databases`, `ecommerce/categories`, `ecommerce/orders`, `ecommerce/products`, `locator/locations`, and the shared `insites`. Each takes `field` (display property) and, for `databases`, `source` (table). They read `modules/insites_crm/crm_company`, platform users, `modules/insites_ecommerce/{category,order,product}` and `modules/insites_locator/location`, 1,000 rows, sorted by the display field. Nothing in the module's Liquid includes them; the caller is outside the module source.

## Email content to reuse

`modules/insites_forms/email_notifications/workflow_content` renders the site-owner body. It takes `form_data` (with `.id`), `form_name`, and optional `title`, `subtitle`, `cta_label`, `cta_link`, `greeting`, `content`. Defaults: "Form Submission Received", a "View Submission" button to `/admin/insites#/databases/<table_id>/items/<id>`, and a field table built by `content_data` (uploads linked by URL, `file_multiple` through `modules/insites_crm/attachment`, markdown, multi-line and code rendered by UI element). `autoresponder_content` is a fixed "Thank you for your enquiry" body. Both sit in CRM's `insites_internal_email_layout` / `insites_external_email_layout`. To change wording per instance, pick `cms_layout` or `visual_editor` in the builder; module files are overwritten on update.

## Admin shell integration

CRM's shell renders `insites_admin/insites_forms_dependencies`, `insites_admin/insites_forms_index_dependencies` (`<div id="insites-forms">` plus the app script) and `insites_menu/insites_forms_side_menu`. The first two are generated by `vue/scripts/write-dependency-partials.mjs`; do not edit.

## Cross-module dependencies

From a grep for `modules/` over the module source on 9 October 2026:

| Module | What Forms uses |
|---|---|
| `insites_crm` (required) | `json` layout; two policies; `functions/response_handler`, `insites_response_handler`, `insites_response_util`, `generate_sort`, `check_version`, `insites_brand`; `controllers/_globals/add_attachment`, `delete_attachments`; `functions/email_sender/resolve`, `customer_sender`; `email_layout/form_notification_from`; `utilities/get_record_for_email`; `hook/get_implementations`, `lib/hooks/hook_module_info`; four email layouts; tables `attachment`, `localisation`, `crm_company`; one image |
| `insites_cms` | `globals` (`company_email_1` as the test email's Reply-To fallback) |
| `insites_databases` | Table names only: user databases are the form `resource`; `file_multiple` presigns target `modules/insites_databases/insites_databases_files` (`GenerateFormCode.js`) |
| `insites_ecommerce`, `insites_locator` | Tables read by the data-source partials |
| `insites_test` | Assertions, tests only |

Minimum CRM at runtime: 6.1.2, checked by `functions/notifications/core_sender_ready`. There is no declarative dependency; the check is the only guard.

## Not extensible

- No webhooks or event names.
- No submission read API; use the Data module ([`../data/api.md`](../data/api.md)).
- No controller aliases.
- The CDN script bundle in `form_code` is unpinned; the viewer pins component bundle `v2.15.1`. Neither is in this repo.
