# Events: Advanced

Extension surfaces of the Events module and what it depends on. Read from `module-v6-events` v6.0.2 on 9 October 2026. Extending Events mostly means consuming the V2 API ([`api.md`](api.md)) or its controllers ([`patterns.md`](patterns.md)); this page covers the rest.

---

## Hook: `hook_module_info`

The only public partial: `public/views/partials/lib/hooks/hook_module_info.liquid`. It queries `modules/insites_crm/hook/get_implementations` for its own install timestamp and returns:

```json
{ "name": "Insites Events", "machine_name": "insites_events", "type": "module",
  "version": "6.0.2", "updated_at": "<timestamp>", "slug": "events", "label": "Events" }
```

Use it to answer "is Events installed"; the version matches the tag at v6.0.2.

## Partials other modules render

These sit under `private/views/partials/` and the module's `CLAUDE.md` names CRM as their consumer (CRM wires Events into the admin shell through them):

| Partial | Purpose |
|---|---|
| `insites_admin/insites_events_dependencies` | preload and stylesheet links for the Events admin bundle; generated by `vue/scripts/write-dependency-partials.mjs`, do not edit |
| `insites_admin/insites_events_index_dependencies` | the `<div id="insites-events">` mount and script tag |
| `insites_menu/insites_events_side_menu` | the `<ins-sidebar-item>` tree (All Events, Tickets, Venues, System Fields, Custom Fields, Webhooks, QR Check-in) |
| `schema/event`, `schema/venue`, `schema/event_ticket` | JSON column definitions with `metadata.label`, `ui_element`, `is_in_column` used by the admin tables |
| `seo` → `event_seo` + `meta_renderer` | renders meta tags for a public event page from `context.params.slug2`; nothing in the module itself includes `seo`, so a site layout is the intended caller |
| `pdf_templates/layout/style` | CSS for the generated ticket PDF |

Treat the GraphQL tables `event`, `event_sponsor`, `event_ticket` and `event_system_field` as a contract too: the module's `CLAUDE.md` records CRM reading them.

## Override points

- **Webhook receiver**: the only runtime extension point. Register a URL per type in IIA and consume `{type, created, data}`; see [`configuration.md#webhooks`](configuration.md#webhooks).
- **Custom fields on events**: define columns in IIA, write them through `custom_field.<name>`.
- **System fields**: add option values through the API; the four fixed fields cannot be renamed.
- **Partial shadowing**: the standard app-over-module rule applies to the partials above; none of them is documented as an override point in the module, so shadow at your own risk and re-test on every module update.
- **Event stream**: admin writes (16 controllers under `controllers/events/`) post audit records through `private/api_calls/event_stream/add_event_stream.liquid` to the Insites event-stream API, authenticated with the instance's event-stream key from CRM. The V2 controllers do not write the event stream.

## Cross-module dependencies

Counted with `grep -rn "modules/<name>" private/`:

| Module | References | What for |
|---|---|---|
| `insites_crm` | 679 lines in 440 files | the two admin policies (127 and 8 pages), `modules/insites_crm/json` layout (108), `functions/insites_response_util` (121) and `functions/response_handler` (50), `functions/get_id` (37), `functions/_external/{payload_api,record_filter,results_api}`, `functions/generate_sort`, tables `crm_company` (54), `crm_contact` (12), `crm_system_field` (12), `attachment` (37), `instance_configurations/get_instance_configuration` (the API key), `system_logs`, `users/get_current_user` |
| `insites_ecommerce` | 17 lines in 17 files | tickets join `modules/insites_ecommerce/order` on `order_number` → `order.id` and return `{id, uuid, order_reference}`; the four `columns/update_columns` controllers include `modules/insites_ecommerce/functions/response_handler` |
| `insites_cms` | 1 | `functions/setup_ticket_pdf_values.liquid` includes `modules/insites_cms/globals` |
| `insites_locator`, `insites_pipeline`, `insites_databases`, `insites_forms`, `insites_assets`, `insites_permissions`, `insites_api` | 0 | none |

CRM is a hard dependency: without it no page authorises and no controller responds. Ecommerce is soft for reads (the `related_record` resolves to null without the table) but the four column-update controllers fail without its response handler. The CMS include makes ticket PDF generation depend on CMS being installed; the source does not guard it.

## Tests

`private/lib/test/` holds nine Liquid tests: seven GraphQL wrappers (areas, divisions, tiers, expenses, user preference, division by import key) and two for the financial summary (`financial_summary_figures_test`, `financial_summary_changed_test`). Run them with `insites-cli test run`.
